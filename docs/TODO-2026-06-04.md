### 5a. Configure the WhatsApp inbound webhook on Meta

Once the function is deployed:

1. Pick a random verify token (e.g. `openssl rand -hex 24`) and paste
   it as `WHATSAPP_WEBHOOK_VERIFY_TOKEN` on the Function App.
2. Open Meta for Developers → your App → WhatsApp → Configuration.
3. Under **Webhook**:
   - Callback URL:
     `https://func-thesrilathaarts-dev.azurewebsites.net/api/webhooks/whatsapp`
     (and the matching `-prd` URL for production).
   - Verify Token: paste the same value from step 1.
   - Click **Verify and save**. Meta hits the URL with a GET that we
     echo back; logs show `whatsappWebhook: verification challenge accepted`.
4. Under **Webhook fields** subscribe to `messages` (covers both
   inbound messages and status callbacks).
5. App Secret: open Meta App → Settings → Basic, click **Show** next
   to App Secret, copy and paste as `WHATSAPP_APP_SECRET`. The
   webhook will reject every POST whose `X-Hub-Signature-256` doesn't
   match this secret.

Smoke check: send a WhatsApp message FROM your phone TO the studio
number. Within a few seconds it should appear at
`/admin/whatsapp` and the order's WhatsApp panel should reflect any
status callbacks.

## P2 — Follow-ups worth doing soon

### A. Public-URL hardening for invoices

`/invoices/{id}.pdf` is reachable without auth (WhatsApp Cloud
needs to fetch it server-to-server). IDs are 14-digit timestamps
which are casually guessable. Options when there's time:

- Add an HMAC token to the URL: `/invoices/{id}.pdf?t=<hex>`,
  validated by `invoiceDownload.ts`. Token is included in the
  branded URL sent over WhatsApp + email + admin.
- Or move the path behind the auth cookie when accessed from the
  web app (separate route for WhatsApp's bot fetch).

### B. Refund notification path

`payments.ts` still enqueues `refund_processed` messages, but the
queue consumer doesn't handle that template yet. Add a
`refund_processed` handler in `notificationsQueue.ts` + matching
email template when refunds get the same treatment.

### C. Email log viewer in admin

`GET /api/admin/orders/{id}/email-logs` is wired but the admin UI
doesn't have a viewer yet. Add a modal or expandable section on the
order detail page that lists each send attempt.

### D. Remove `enqueueNotification` call sites that have no consumer

Audit any remaining `enqueueNotification` calls with `templateKey`
values that aren't in `notificationsQueue.ts`'s switch. Today
that's `refund_processed` and any future ones. Either implement
the handler or stop enqueueing.

### E. Move SMTP_PASS to Key Vault

Currently set as a plain Function App application setting. Wrap
in a Key Vault reference so secret rotation doesn't require a

## Reference

- Order #/Invoice # format: `YYYYMMDDHHMMSS` (IST), 14 digits.
- Branded URL: `https://www.srilatha.art/invoices/{InvoiceNumber}.pdf`
  → SWA rewrite → `/api/invoices/{file}` → blob stream.
- Single source of truth: PDF lives at
  `{INVOICE_CONTAINER}/{InvoiceNumber}.pdf`. Every channel reads
  from there; nothing regenerates downstream.
- WhatsApp template: `order_confirmation_new_artwork`,
  `{{1}}=customerName`, `{{2}}=orderId`, DOCUMENT header.
- Notifications queue: `notifications-out` (env
  `NOTIFICATIONS_QUEUE_NAME`). Poison queue:
  `notifications-out-poison`.
