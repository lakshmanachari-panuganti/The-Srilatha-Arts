1.1 "Non-button input shapes were changed" (Medium in the original v1 draft;
    withdrawn in the updated review)

    Flagged files:
      - frontend/components/Footer.tsx (newsletter email input)
      - frontend/app/cart/page.tsx (coupon input)
      - frontend/app/checkout/CheckoutClient.tsx (coupon input)

    Verdict: FALSE POSITIVE (scope, not fact).
    The factual observation was accurate — these three input radii were
    changed. However, the classification as a violation is incorrect:

    a) The product owner has explicitly confirmed that non-button input
       boxes are also in scope for the soft-rectangle conversion
       ("non-button input boxes also should change").

    b) Even before that clarification, the change was functionally
       necessary: each of these inputs sits directly beside a converted
       button as a combined control (input + Subscribe, input + Apply).
       Leaving a 999px capsule input beside a 6-8px rectangular button
       would have produced a visibly broken pairing.

    The updated review correctly removed this from "Unnecessary Changes";
    this section documents the rationale for the record. Inputs have since
    been standardized at 8px site-wide (.form-input token 12px -> 8px,
    WhatsApp inbox search input and reply textarea, footer newsletter,
    coupon inputs).

-----------------------------------------------------------------------

2.1 "Jest exits with code 1: all 82 assertions pass, but cart background
    synchronization logs failed fetches after tests finish"

    Verdict: PLAUSIBLE BUT UNVERIFIED in this environment.
    Reproduction was attempted (npx jest in frontend/); the run could not
    complete within the session's execution limits because the repository
    is accessed over a slow mounted filesystem — the run was still
    resolving dependencies after several minutes and was aborted.

    Supporting evidence for plausibility (from code inspection of
    frontend/stores/cart.ts):
      - Line ~58:  console.warn('[cart] background sync failed', err)
      - Lines ~99-128: add/remove/clear operations issue fire-and-forget
        apiFetch() calls ("Best-effort server sync") whose rejections are
        caught but logged.
    In a Jest run with no live backend, these background promises settle
    (and log) after the test suite has completed, which is a recognized
    cause of Jest exiting non-zero ("Cannot log after tests are done" /
    open-handle detection) despite all assertions passing.

    Important context: even if confirmed, this behavior is pre-existing
    and unrelated to the UI radius change, which touched only CSS
    border-radius values and Tailwind radius classes (verified via git
    diff: every changed line is a radius-class or border-radius edit).

2.2 "No browser screenshot comparison was available" (listed under
