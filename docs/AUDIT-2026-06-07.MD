# Website Audit Report - Top 5 Immediate Fixes

**Date:** 2026-06-07
**Auditor:** Senior Full-Stack Developer & Technical Lead

Based on a deep, end-to-end technical analysis of the Srilatha Arts project, I have identified the top 5 highest-priority issues ranked by severity, business impact, and risk. No code changes have been made during this audit.

---

## 1. CRITICAL: Cross-Origin Cookie Domain Mismatch Breaks Auth & CSRF
**Category:** Functionality & Security
**Location:** `backend/src/services/auth.ts` and `backend/src/services/csrf.ts`

**The Problem:**
The backend API is hosted at `func-thesrilathaarts-prd.azurewebsites.net`, but the cookie builder explicitly sets `Domain=.srilatha.art` (via the `COOKIE_DOMAIN` env variable in production). Browsers enforce strict security policies and will flatly reject any `Set-Cookie` header where the requested domain does not match the origin server's domain. 

**Business Impact:**
- **CSRF is completely broken:** The `tsa_csrf` cookie is never saved by the browser. Any POST, PATCH, or DELETE request relying on CSRF verification (like `api/checkout`, `api/auth/profile`) will fail.
- **Auth Persistence:** The `tsa_token` cookie fails to save, breaking cross-tab session persistence and leading to poor user experience.

**Remediation:**
Remove `Domain=.srilatha.art` when the API is hosted on a different registrable domain than the frontend. Rely on the browser's default behavior (which locks the cookie to the exact origin) and ensure `SameSite=None; Secure` is used consistently across both the CSRF and Auth cookies.

## 2. CRITICAL: Rate Limit Bypass via X-Forwarded-For Spoofing
**Category:** Security (Brute Force / Credential Stuffing)
**Location:** `backend/src/functions/adminAuth.ts` and `backend/src/functions/userAuth.ts`

**The Problem:**
The `getClientIp` function extracts the client IP using `request.headers.get('x-forwarded-for')?.split(',')[0]`. In Azure (and most cloud proxies), the left-most IP in the `X-Forwarded-For` chain is user-provided, while the proxy appends the true client IP to the right. 

**Business Impact:**
Attackers can trivially bypass the 10-attempts-per-15-min rate limit by spoofing the `X-Forwarded-For` header with a different random IP on every request. This leaves the `adminLogin` and `userLogin` endpoints completely vulnerable to brute-force and credential stuffing attacks.

**Remediation:**
Extract the true client IP provided by Azure using the `x-ms-client-ip` header, or configure the app to only trust the right-most IP in the `x-forwarded-for` chain added by the Azure proxy.

## 3. HIGH: Unauthenticated Access to PII via Guessable Invoice URLs (IDOR)
**Category:** Security & Data Privacy
**Location:** `backend/src/functions/invoiceDownload.ts`

**The Problem:**
The endpoint `GET /api/invoices/{InvoiceNumber}.pdf` serves customer invoices without any authentication checks. The `InvoiceNumber` is generated using a timestamp (`YYYYMMDDHHMMSSFF`), making it predictable and guessable.

**Business Impact:**
An attacker can write a simple script to brute-force timestamp ranges and download hundreds of invoices. These PDFs contain highly sensitive Personally Identifiable Information (PII) including full names, physical addresses, phone numbers, and purchase histories, leading to a severe data breach.

**Remediation:**
Do not rely on guessable IDs for access control. Either require authentication via the `tsa_token` before streaming the blob, or append a cryptographically secure, unguessable HMAC token to the public URL that must be validated before serving the PDF.

## 4. HIGH: Long-Lived Stateless JWTs without Revocation Mechanism
**Category:** Security
**Location:** `backend/src/services/auth.ts`

**The Problem:**
JWTs (`tsa_token`) are issued with long expirations (7 days for users, 24 hours for admins). Because the tokens are entirely stateless, the backend does not maintain a blocklist or session table.

**Business Impact:**
If an admin's device is compromised, or a user account is taken over, there is absolutely no way to revoke their access until the token naturally expires, short of rotating the global `JWT_SECRET` (which would log out every single user on the platform). 

**Remediation:**
Transition to short-lived access tokens (e.g., 15 minutes) paired with long-lived, rotating refresh tokens stored in Azure Table Storage, or maintain a high-performance token blocklist (e.g., using Redis or Table Storage) to allow immediate revocation of compromised sessions.

---

## 5. MEDIUM-HIGH: Weak Content Security Policy (CSP) allowing 'unsafe-inline'
**Category:** Security (XSS)
**Location:** `frontend/staticwebapp.config.json`

**The Problem:**
The `Content-Security-Policy` header explicitly allows `'unsafe-inline'` for `script-src`. 

**Business Impact:**
This entirely defeats the primary purpose of a CSP. If an attacker finds a Cross-Site Scripting (XSS) vulnerability anywhere in the React application (e.g., unescaped user input in a product review or custom order note), they can inject inline `<script>` tags to execute malicious JavaScript, steal sessions, or deface the checkout flow.

**Remediation:**
Remove `'unsafe-inline'` from `script-src`. Use nonces (`'nonce-xyz'`) or strictly whitelist external script domains. If Next.js requires inline scripts for static exports, consider utilizing strict hashes (`'sha256-...'`) for those specific inline blocks.
