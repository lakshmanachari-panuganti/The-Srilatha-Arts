## Steps

### Step 1 - Create the AAD app registration that represents v2's API

Run once (Cloud Shell or your terminal, signed in as a tenant admin):

```powershell
$TENANT_ID = "d4447f09-6c75-4479-8911-019da3f93632"
$APP_NAME  = "app-srilathaartwhatsappv2-api"

# 1a. Create the app registration WITHOUT --identifier-uris first
#     (tenant policy requires the URI to contain the tenant ID or app ID,
#      so we set it after we have the appId)
$APP_ID = az ad app create `
    --display-name $APP_NAME `
    --sign-in-audience AzureADMyOrg `
    --query appId -o tsv
Write-Host "App registration appId = $APP_ID"

# 1a-cont. Wait for AAD replication, then set the identifier URI
#           (az ad app update fails immediately after create due to replication lag)
Write-Host "Waiting 15 s for AAD replication..."
Start-Sleep -Seconds 15
$IDENTIFIER_URI = "api://$APP_ID"
az ad app update --id $APP_ID --identifier-uris $IDENTIFIER_URI
# Confirm
az ad app show --id $APP_ID --query identifierUris -o tsv

# 1b. Create the matching service principal (required for Easy Auth + role assignments)
$SP_ID = az ad sp create --id $APP_ID --query id -o tsv
Write-Host "Service principal objectId = $SP_ID"
```

Save `APP_ID` and `SP_ID` - you'll need them in step 2 and step 3.

### Step 3 - Grant the website backend MI that app role

The website backend's MI (`a8a495fe-…`) needs the `Messages.Access.Srilatha` role on the v2 app registration.

```powershell
# Look up the app role id you just created

    --query "appRoles[?value=='Messages.Access.Srilatha'].id | [0]" -o tsv
Write-Host "App role id = $APP_ROLE_ID"

# Grant the website backend MI that role on v2's SP
$WEBSITE_BACKEND_MI = "a8a495fe-bd7e-409e-a7dd-ccbb92305113"

$body = @{
    principalId = $WEBSITE_BACKEND_MI
    resourceId  = $SP_ID
    appRoleId   = $APP_ROLE_ID

az rest --method POST `
    --uri "https://graph.microsoft.com/v1.0/servicePrincipals/$WEBSITE_BACKEND_MI/appRoleAssignments" `
    --headers "Content-Type=application/json" `
    --body $body
```

Expected response: `201 Created`. A repeated call returns `400` with `Permission being assigned already exists` - that's idempotent-safe.

### Step 6 - Add CORS for the admin SWAs

```powershell
$RG = "rg-srilathaartwhatsappv2-shared"
$FA = "func-srilathaartwhatsappv2"

az functionapp cors add --resource-group $RG --name $FA `
    --allowed-origins `
        "https://salmon-wave-01c7b8300.7.azurestaticapps.net" `
        "https://delightful-mushroom-062e18100.7.azurestaticapps.net"

# Custom domain mapped to PRD SWA - browsers send this as Origin, not the azurestaticapps.net URL
az functionapp cors add --resource-group $RG --name $FA `
    --allowed-origins "https://www.srilatha.art"

# Verify
az functionapp cors show --resource-group $RG --name $FA -o json
```

Note: Easy Auth and CORS are independent. The browser will send the preflight `OPTIONS` request first, which Easy Auth lets through; the actual `GET`/`POST` then arrives with the bearer token.
